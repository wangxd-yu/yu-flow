# 版本发布与跨环境

开发环境改编排，生产环境只接收发布包。一条版本从「版本单」到「目标环境已上线」走完下面四步，不在生产上直接改接口、服务、任务或页面。

菜单在 **版本发布**：开发环境用「版本单」，目标环境用「发布包导入」和「导入记录」。

## 环境要先配好

两套环境（或同一套里的开发实例和生产实例）约定这些变量。口令类不要写进仓库。

| 变量 | 开发实例 | 生产实例 |
|------|----------|----------|
| `YU_FLOW_CURRENT_ENV` | `DEV` | `PROD` |
| `YU_FLOW_RELEASE_SIGNING_KEY` | 与生产相同 | 与开发相同。配了之后导出带签名，导入必须验签 |
| `YU_FLOW_RELEASE_PREVIOUS_SIGNING_KEYS` | 轮换期间的旧密钥，逗号分隔，只验签不签名 | 同左 |
| `YU_FLOW_LOCK_ASSET_EDITING` | `false` | `true`。页面上不能再直接改编排资产 |

生产实例还要满足[生产环境加固清单](../advanced/production-hardening.md)里的密钥和口令要求。

权限按角色分：

| 谁 | 权限 | 能做什么 |
|----|------|----------|
| 开发 | `flow:release:pkg:edit` | 建版本单、加资产、冻结、导出 |
| 运维 | `flow:release:import` | 预检并导入发布包（导入即发布） |
| 运维 | `flow:release:rollback` | 按导入记录回滚到导入前的备份 |
| 只读 | `flow:release:pkg:view` | 看版本单和导入记录，不能改 |

内置角色「运维实施」（`DEPLOYER`）拥有导入、回滚和环境变量维护，没有直接改编排资产的权限。适合开了编辑锁的生产实例。

## 1. 开发环境做版本单

1. 打开 **版本发布 → 版本单**，新建一张草稿。版本号只能是字母、数字、点、下划线和中划线，例如 `v2026.10`。备注会写进发布包里的 `CHANGELOG.md`。
2. 在接口、服务、任务等列表里勾选资产，用 **加入版本单** 放进这张草稿。也可以在版本单详情里扫描近期变更。依赖（内部服务、响应模板等）会按选择一并带上。
3. 需要在目标环境下线的资产，用下线清单，不要只是从版本单里删掉。
4. 点 **检查**。未发布、有未发布改动、或引用了版本单之外的资产时，错误必须先处理，警告要看过再继续。
5. 点 **冻结**。冻结后内容指纹固定，资产再改也不会悄悄进这张包。
6. 点 **导出发布包**，得到 `.yfpkg`。交给运维的就是这个文件，不要改扩展名，也不要自己解压再打包。

已导出的版本单留作上线记录，不能删除。内容要改时重新冻结并导出。

## 2. 目标环境导入

在生产（或预发）打开 **版本发布 → 发布包导入**。

1. 上传 `.yfpkg`。先做预检，不写库。预检会核对签名、版本号是否已导入过、以及目标环境缺哪些依赖。
2. 发布包里如果有占位符（数据源、环境变量一类要在目标环境填的值），按页面提示补齐后再执行。
3. 确认版本号后执行导入。导入成功即发布：编排资产写成线上快照，定时任务和 MQ 按包内状态生效。
4. 导入前的内容会做备份。到 **导入记录** 可以查看这次导入了什么。

签名对不上、包被改过、或者生产没配 `YU_FLOW_RELEASE_SIGNING_KEY` 时，导入会被拒绝。两套环境的签名密钥必须是同一个值。

编辑锁打开后，生产上的「加入版本单」和资产编辑入口不可用。要改生产，只能回到开发环境出一张新的发布包。

## 3. 回滚

导入后业务不对，到 **版本发布 → 导入记录**，对那一次成功导入执行回滚。回滚用的是导入前自动留下的备份，把当时被覆盖的资产恢复回去。

只保留最近若干次成功导入的备份（`YU_FLOW_RELEASE_BACKUP_RETENTION`，默认 10）。更早的记录还在，但已经没有备份，不能再回滚。

回滚不会生成一张反向的版本单。回滚之后如果开发环境的草稿已经继续改过，下一张发布包要按当前生产内容重新对比，避免把回滚掉的改动又带回来。

## 4. 空库初始化

新环境第一次启动前执行建表脚本，顺序不能反：

1. `flow-api/sql-mysql/00_all_flow_tables.sql`（瀚高 / PostgreSQL 用 `flow-api/sql-pg/` 下的同名文件）
2. 对应目录的 `00_system_init.sql`

Docker 试用编排会在 MySQL 数据卷第一次创建时自动跑这两份脚本，并跳过种子里指向本机的数据源行。已经在跑的库不要整份重灌。
