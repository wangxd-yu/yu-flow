# 🛡️ 演示模式安全管控

在搭建开源演示环境或企业内部培训沙箱时，我们通常希望用户能够充分体验系统的编排功能，但又绝对不能修改核心资产或将系统“挂死”。

Yu Flow 内置了**硬件级防御的演示模式（Demo Mode Guard）**，只需一个环境变量即可开启。

## 开启方式

在部署时（例如 `application.yml` 或 Docker 环境变量中）设置：

```yaml
yu-flow:
  demo-mode:
    enabled: true
    max-steps: 100
```

## 核心防御机制

当演示模式开启后，系统将自动激活以下安全屏障：

### 1. 资产写入锁定
通过全局 `DemoModeInterceptor`，系统会拦截所有非 `GET`（如 POST, PUT, DELETE）的高危操作。这意味着用户只能查看数据，无法新建、修改、删除任何核心资产（如 API 定义、系统配置等）。
- *注：系统对登录审计日志等核心日志数据的写入进行了安全放行，确保系统监控不受影响。*

### 2. 画布执行防挂死
如果不加限制，恶意用户可能会在画布中画一个无限循环的 `If` 节点，瞬间耗尽服务器 CPU 资源。
- 当开启演示模式时，引擎自动将允许执行的最大节点数限制为配置的值（如 `100` 步）。
- 一旦某次请求超过了 `100` 个节点的流转，引擎将立即主动抛出异常（`FlowException`），从而保护宿主机不被拖垮。

### 3. 系统函数黑名单
在沙箱脚本引擎（Aviator / GraalJS / SpEL）中，禁止调用 `System.exit()` 等系统级高危方法。

## 用户体验

在前端，系统会通过轮询接口感知演示模式的开启状态。当开启时，核心配置界面的“新建”、“编辑”、“删除”按钮会自动隐藏，避免用户点击后无谓报错，提供极佳的沉浸式只读体验。
