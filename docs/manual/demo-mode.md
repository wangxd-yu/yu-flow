# 🛡️ 演示模式安全管控

在搭建开源演示环境或企业内部培训沙箱时，我们通常希望用户能够充分体验系统的编排功能，但又不能破坏预置资产或将系统「挂死」。

Yu Flow 内置 **演示模式守卫（Demo Mode Guard）**，只需一个配置项即可开启。

> **能力边界（先读）**：演示模式是「**预置资产锁 + 数据库写禁止 + 防挂死限制**」，**不是全局只读**。访客仍可以创建**新的**资产进行体验（这正是演示的目的）；被保护的是启动时已存在的预置资产与底层数据库数据。

## 开启方式

在部署时（`application.yml` 或环境变量）设置：

```yaml
yu:
  flow:
    # 总开关（环境变量 YU_FLOW_DEMO_MODE=true）
    demo-mode: true
    # 以下限制项仅在 demo-mode=true 时生效
    demo:
      max-steps: 200          # 单次流程执行最大节点步数
      max-for-loop-items: 50  # For 循环最大输入数组元素数
      max-delay-ms: 5000      # Delay 节点最大等待毫秒数
```

## 核心防御机制

### 1. 预置资产锁定（非全局只读）

启动时 `DemoModeGuard` 将数据库中**已存在**的资产 ID（API、模型、数据源、目录、宏、页面、系统参数、定时任务、服务编排、开放平台等）载入内存保护名单：

- 名单内资产的**修改 / 删除**请求被拦截，返回 `DEMO_RESTRICTED` 友好提示；
- 访客**新建**的资产不在名单内，可自由编辑、删除，完整体验编排流程；
- 非演示环境下守卫空载运行，性能零损耗。

### 2. 数据库写入禁止

Flow 引擎内的 Database 节点禁止执行 `INSERT / UPDATE / DELETE`；API 管理界面禁止新建或修改为写入类（INSERT/UPDATE）接口，防止演示库被污染。

### 3. 画布执行防挂死

- 单次执行超过 `max-steps` 节点步数即抛出 `FlowException`，阻断死循环；
- For 循环输入数组超过 `max-for-loop-items` 被拒绝，防止线程池 / 内存耗尽；
- Delay 节点等待时长受 `max-delay-ms` 上限约束。

### 4. 脚本引擎沙箱

沙箱脚本引擎（Aviator / GraalJS / SpEL 等）中禁止调用 `System.exit()` 等系统级高危方法（该防线与演示模式无关，始终生效）。

## 用户体验

前端统一捕获 `DEMO_RESTRICTED` 错误码，以温和的提示气泡告知「预置资产不可修改，可创建新资产体验」，而不是抛出原始报错。

## 与生产加固的关系

演示模式解决的是「公开演示环境不被写坏」；生产嵌入部署的默认值收紧（host-demo、auth-none、开放平台等）见 [生产环境加固清单](../advanced/production-hardening.md)。
