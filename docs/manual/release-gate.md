# 环境发布门禁与回归测试

Yu Flow 的发布仍是「草稿 → 一份线上快照」，但在发布前增加了**逻辑环境**与**回归门禁**，避免预发/生产误发未验证内容。

> 这里的 DEV / STAGING / PROD 是**发布策略**，不是三套独立线上资产库。网关始终只读当前那一份 `publishedSnapshot`。

## 三个环境怎么选

| 环境 | 何时用 | 是否要求回归通过 | 通过结果有效期 |
|------|--------|------------------|----------------|
| **DEV** | 日常联调、探索改动、培训 | 否 | — |
| **STAGING** | 上线前准生产确认 | **是** | 48 小时 |
| **PROD** | 正式对外 / 正式调度前 | **是** | 24 小时 |

### 推荐工作流

1. **改草稿** → 调试器跑通  
2. 在编辑页「回归测试」维护用例（请求样例 + 期望 `success` / JSONPath）  
3. 运行套件，环境选 **STAGING**（或即将发布的环境）  
4. 点「发布」→ 同一环境 → 门禁通过后才写入线上快照  
5. 若团队约定「生产标签更严」：再对 **PROD** 跑一次回归并以此环境发布  

### 定期巡检

在接口列表勾选多个接口 → **批量回归** → 选择环境 → 查看通过/失败/无套件跳过。适合发版日冒烟与每周核心接口健康检查。

## 回归如何执行（安全）

- 只通过**内部引擎**执行当前**草稿 DSL**，**不能**填写外连 URL（防 SSRF）  
- 禁止保存 `Authorization` / `Cookie` / `*Token*` 等敏感请求头  
- 断言仅支持简单 JSONPath（如 `$.status`、`$.outputs.code`）  
- 有用例数量、包体大小、超时与并发上限  
- **业务库写默认回滚**：`DEBUG` / `REGRESSION` 下 Database 节点的 INSERT/UPDATE/DELETE 在流程结束后回滚（同数据源内后续步骤仍可读到本次写入）；线上正式调用不回滚  

P0 重点支持 **FLOW 类型接口**；非 FLOW 接口会在运行时提示不支持。

## 操作入口

| 位置 | 作用 |
|------|------|
| 接口编辑页 → 回归测试 | 套件 / 用例 / 单资产运行 |
| 发布确认弹窗 | 选环境并查看门禁明细 |
| 接口列表 → 批量回归 | 多资产定期巡检 |

任务、服务发布同样受门禁约束。

## 初始化 SQL

首次使用请执行：

```text
flow-api/sql/release_gate.sql
```

需要权限：`flow:release:view`（查看/预检）、`flow:release:edit`（管理套件与运行）。

## 常见问题

**Q：选了 PROD 发不出去？**  
A：该环境要求 24 小时内有 PASSED 的回归记录。先建套件、对该环境执行运行，再发布。

**Q：DEV 还要不要写用例？**  
A：不强制。但对核心接口建议尽早补用例，否则切 STAGING/PROD 时会被门禁拦住。

**Q：回归通过了，线上还是旧逻辑？**  
A：回归只验证草稿；必须再点「发布」才会更新线上快照。
