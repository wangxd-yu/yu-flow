# 📡 执行大盘与只读回放

Yu Flow 为动态 API 提供了开箱即用的**企业级调用链路追踪（Trace）与可视化回放能力**，彻底颠覆了传统的日志排查体验。

## 什么是执行大盘？

在传统开发中，当某个接口在生产环境报错时，开发人员通常需要去服务器拉取海量文本日志，通过 `grep` 关键词一点点拼凑当时的执行现场，耗时且极易出错。

Yu Flow 的「执行日志大盘」通过无侵入式的拦截器，自动捕获所有动态 API 的执行情况，并将其持久化到数据库中。您可以直接在可视化的管理后台查看：

- 接口请求路径与耗时
- 执行结果状态（成功 / 失败）
- 触发时间与 IP

## 毫秒级高保真只读回放

这是 Yu Flow 独创的“杀手级”功能。针对 `FLOW` 类型的复杂编排接口，我们会在执行时生成一份包含当时拓扑结构和所有变量状态的「快照（Snapshot）」。

### 如何使用？

1. 进入 **执行日志** 页面。
2. 找到任意一条 `FLOW` 类型的执行记录。
3. 点击右侧操作栏的 **查看快照**。
4. 此时，界面下方会弹出只读模式的 X6 画布控制台：
   - **高亮路径**：成功执行过的节点会变为绿色，一目了然。
   - **变量切片**：点击任意一个执行过的节点，右侧面板会展示该节点执行**前**和执行**后**的完整上下文变量（JSON 格式）。

> **💡 提示**：即使 API 的原始画布在后来被修改或删除了，历史记录中的回放依然不受影响，因为回放使用的是当时瞬间截取的快照数据。

## 对于非 FLOW 接口（DB / JSON）

如果接口类型是简单的 `DB` 连库查询或 `JSON` 静态返回值，我们提供了一个极简版的 `SimpleTraceViewer`。

回放时，您将直接看到一个清爽的面板，展示：
- **入参（Inputs）**：当时的 Query 参数和 Body
- **出参（Outputs）**：数据库查询结果或生成的 JSON
- **异常堆栈**：如果执行报错，会直接高亮显示具体的异常堆栈信息。

## 性能保障机制

追踪如此详细的数据，会影响 API 的吞吐量吗？**不会**。

1. **全异步化架构**：日志的生成和入库完全跑在独立的异步线程池（`AsyncConfig`）中，对主业务线程的阻塞时间趋近于零。
2. **轻量级列表查询**：大盘列表页使用的是剔除了庞大快照数据的 `FlowExecutionLogListDTO`，保证了百页以内查询依然秒开。
3. **JPQL 批量清理**：系统内部自带定期清理任务，利用 JPQL 底层进行 Bulk Delete，确保系统长久运行不 OOM。
